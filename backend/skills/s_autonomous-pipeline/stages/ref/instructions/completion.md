## What the Pipeline Delivers — the North Star (full text; the card has the summary)
A run does NOT deliver "a code change." It delivers an **accountability unit of work**: a
commit/PR an engineer could hand their manager and defend — code **plus** a short, honest report
of what was built, why, and what was learned, in ONE reviewable object. The commit is the
deliverable; the diff is only part of it.

**REPORT.md is a report to a boss, not a log of every detail.** Keep the existing structure
(`cmd_run_report` projects it from the ledger — intent→requirement provenance, key decisions,
reflect lessons, files changed, outcome). Two editorial principles prune what goes IN each
section; they do not redefine the structure:
- **Omit the fine-grained detail.** Carry what a human will actually review — the
  intent→requirement derivation, the decisions a reviewer would challenge, the lessons, what
  changed and whether it works. NOT the process minutiae (every gate's internal mechanics, every
  RP checked, how a mutation ran, internal tooling debates, raw TEST metric counts).
- **Omit the uncertain.** If something was not actually done or you are not sure of it, leave it
  out. Omitting is honest; a precise-looking but hand-fabricated value is worse than nothing. At
  commit time REPORT.md is a truthful SELF-REPORT and CI post-push is its independent auditor — so
  never dress a self-reported number as a verified fact.
