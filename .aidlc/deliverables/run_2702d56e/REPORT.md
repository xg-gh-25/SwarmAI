## TL;DR
**解决了什么问题**
- 原来：The test runner's reports (test results that decide landing, break-test proofs that close Gate-2 findings, round snapshots, the old-side cache) lived in a directory the agent can write, and every reader trusted them, so a hand-written prove file or latest-regression.json counted as the runner's.
- 现在：For every run created from now on, a runner report counts only when its bytes match the sha the runner recorded in a protected per-run store; a hand-written, edited, restored, symlinked or removed report is present-but-unusable, and a tampered run index makes the caps refuse instead of resetting.

**怎么做的**
- core/evidence_seal.py seals at the runner's single writer and checks at every reader with one read
- symlinks below runs/<id> are rejected and seal keys are not resolved through them
- enable is recorded in the hand-out ledger too, so a vanished store rejects; an unreadable store fails open with a warning

**遗留问题**（5 条，见 §10）

## 1. Requirement
P0-1 runner evidence seal: evidence the test runner writes under a run's evidence/{tests,proofs,probes,mutations}/ is sealed (latest sha per file) in a per-run store in the protected agent-audit dir (core/evidence_seal.py, written by pipeline_test._write_json); every reader (pipeline_validator._load_evidence_json, pipeline_test._read_json, artifact_cli._merged_proofs) treats an unsealed or changed file as present-but-unusable. Enforced only for runs whose seal store was enabled at run-create; an unreadable store fails open with a reason. A hand-written prove file or latest-*.json no longer closes a finding or lands code.

## 3. Design & Approach
**Chosen Approach:** New module backend/core/evidence_seal.py: run_of(path), enable(run_id), seal(path), check(path) -> (ok, reason). The store is a protected file next to the hand-out ledger, written under its own flock. pipeline_test._write_json seals after the atomic replace; pipeline_test._read_json and pipeline_validator._load_evidence_json return no data for a file check() rejects; artifact_cli._merged_proofs reads prove files and snapshots.json through pipeline_validator._load_evidence_json; cmd_run_create calls enable().

**Success Criteria:**
- test_evidence_seal.py green
- test_gate2_next.py and the runner's own tests green

**Always:**
- fail open when the store cannot be read (no self-lock on an infra error)
- check only runner-written subdirs

**Never:**
- write the seal store from a shell command or by hand
- check files the CLI writes (prompts, gate2-v2.json, fixing-spec)
