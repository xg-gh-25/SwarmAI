# CDF：带着上下文的 agent 做判断，删掉在它之后二次评判的机制

## 0. 原则

XG 2026-10-30 的指示：**CDF 是 agent 自己的认知引擎。** 什么该沉淀、放到哪里、要不要限制大小，都由 agent 自己决定，不拿来问人。沉淀的目的，是让 agent 之后能自主判断、交付得更好。硬约束只有一条：**不影响整个系统的性能。**

由此得出一条划分：

| 判断的性质 | 谁来判断 |
|---|---|
| **含义**：这算不算知识、属于什么类型和范围、放到哪里、是新的还是已有的、是否覆盖旧条目、这次纠正是不是旧错重犯 | **产出它的那个 agent**，它手里有完整上下文：对话中的 agent（S1）、会后复盘（S7）、写 REFLECT 的 run agent（S3） |
| **安全与存储**：有没有密钥或注入、证据是否真实存在、是否逐字重复、谁有权写用户自己的文件、写入格式、失败重试 | 确定性代码 |

**不允许**一个更弱的判断者，在 agent 之后推翻或改写它的判断。更弱的判断者包括：正则、关键词或 BM25 匹配、固定规则，以及看到更少上下文的模型调用。

## 1. 现状：判断点和判断者

以下数据来自线上 `ingestion.db` 只读查询，覆盖 v2 上线以来约 1.5 天；行号以当前 main 为准。

1. **verify 判官**（`prompts.py:239-295`，`pipeline_v2.py:645-672`）。由 Sonnet 判断 grounded、durable、self-contained，以及新单元和已有条目的关系。它**看不到会话**，只能看到单元 JSON、被引用的用户原话和 BM25 找回的条目。
   - S7 单元被判为无依据 220/305 条，S1 是 7/7 条。
   - 判定结果会触发 `_not_grounded`（`:520-558`）：EVOLUTION 和 MEMORY 的单元被改道到项目 DDD 或者拒收，DDD 单元被标成 `inferred`，进而被标上 `taint:external`。
   - v2 上线后，S7 新写进 EVOLUTION 的条目是 **0 条**。
2. **taint 自我传染**（`session_inputs.py:58,92`，`provenance.py:284-300`，`writer.py:513,1115-1127`）。所有工具结果都被当成外部内容，所以 S7 和 S3 的单元 100% 带 taint。带 taint 的单元发起的覆盖全部被拒（`overrides.py:111`），结果是旧知识永远退不出去。
3. **S7 资格阈值**（`s7_review.py:77-104`）。用正则加计数决定一个会话要不要复盘，不够阈值的会话就没有复盘。

5. **正则拒收**。D4"易变"（`pipeline_v2.py:54-58,604-607`，`rules/ddd.py:15-16`）拒了 17 条；遇到 `<!--` 直接拒收（`:196-212`）拒了 4 条。
6. **固定规则拒收或挂起**。`unknown_project` 拒了 52 条（`:576-599`）；`unknown_domain` 挂起 61 条，而且已经没有任何代码能放它们出来（`worker.py:744-756`）。

9. **抓纠正的正则**（`runtime_hooks.py:61-121,303-357`）。线上指标 O3 和 skill 满意度都按这个正则统计。
10. **Hive 教训要人点"收下"**（`hive_lessons.py:336-372`）。收下之后，在 host 上又被当成外部内容重新判一遍。

## 2. 删除与改动

| # | 删 / 改 | 改成 | 不影响性能的理由 |
|---|---|---|---|
| D1 | **删** verify 判官，连同它对准入、路由、标记的否决权，以及它的 BM25 候选检索（`card3.retrieve` 在 v2 里的用法） | 产出方在单元里**声明**它和已有条目的关系：`new`、`same:<id>`（并入，只加证据）、`overrides:[{id, head}]`（现有机制）；纠正类单元另声明 `repeats:<id>`。确定性代码只核对被声明的 id 真实存在、且属于同一 Brain | 少一次模型调用，每个单元省掉一次判官 |
| D2 | **改** taint：本会话自己的工具输出不再算外部内容。外部内容只包括网页抓取、外部 MCP 内容、Signals、外部文档，以及 Hive 带回来的外部来源 | 吸收 fixing spec 的 C1：分成 `read_external` 和 `cited_external` 两个概念 | 无 |
| D3 | **删** S7 资格阈值 | 每个有用户消息的会话都复盘；没有值得沉淀的就什么也不产出 | 复盘在后台跑，沿用现有的内存预算推迟（`worker.py:994-1024`），聊天路径不变 |
| D4 | **删** S2 的认知抽取（两轮都删） | S7 是唯一的会话抽取者，事件也由 S7 产出。会话无法 resume 时，把 transcript 文本交给同一个 S7 prompt 来跑 | 少一份 Sonnet 抽取的开销 |
| D5 | **删** D4"易变"正则 | 交给抽取提示词约束，由 agent 自己判断 | 无 |
| D6 | **改** `<!--` 从拒收改为转义 | writer 写入时转义 | 无 |
| D7 | **改** `unknown_project` 从拒收改为落到 General Brain | — | 无 |
| D8 | **删** `unknown_domain` 挂起路径 | 现存的 61 条走一次新流程（§4） | 无 |
| D9 | **删** EVOLUTION、MEMORY 的"信任改道" | agent 声明的 scope 就是去向。用户自己的文件仍然要求证据是用户本人的消息，见保留项 K3 | 无 |
| D10 | **删** S7 单次 15 条上限；**改** scope=user 的单元不再丢弃，按 K3 处理 | — | 无 |
| D11 | **删** 每日写入额度；同步改 AGENT R22 的治理文字 | 每轮注入的预算保留（K6），每轮 prompt 的大小不变 | 写入额度和每轮的成本无关 |
| D12 | **删** 抓纠正的正则 | O3 和 skill 满意度改为读 S7 抽到的 `correction` 单元（按会话）；重复纠正率 = 带 `repeats` 的纠正 ÷ 全部纠正 | 每条用户消息少跑一次正则 |
| D13 | **删** Hive 教训的人工"收下"，以及在 host 上的重新判定 | 随 run 记录自动进 CDF。外部来源仍按 `cited_external` 标记 | 无 |
| D14 | **改** 注入排序去掉时间衰减项（`memory_injection.py:279`），和 v5"不按时间衰减"保持一致 | 按支持和使用排序 | 无 |

**S7 的输入要补一样东西**（D1 依赖它）：复盘时给 S7 一份目标 Brain 里和本次会话最相关的已有条目（id、首行），以及 EVOLUTION 里已有的纠正（id、首行）。S7 据此判断 new、same、overrides 或 repeats。这一步只是**检索**（BM25 取前 N 条），不做任何判断，判断由 S7 来做。会话中被召回过的条目本来就在 fork 出来的上下文里。

**S7 模型保持 Sonnet。** 这是 XG 在 2026-10-29 出于成本做的决定（`s7_review.py:45-48`）。S7 带着整段会话的上下文，不是"傻子"；真正的问题出在 D1 的判官。

## 3. 保留（这些不是在判断含义）

- **K1 安全扫描**：密钥、注入、带凭证的 URL（`provenance.py:285-300`，MemoryGuard）。
- **K2 证据完整**：证据必须真实存在于本会话或本 run（`evidence_not_in_index`、`provenance` 的解析）。
- **K3 用户自己的文件**（STEERING、USER、TOOLS）：证据必须是用户本人的消息，并且没有 `read_external`。这是归属和安全规则，由代码逐字核对引文，不做语义判断。
- **K4 逐字重复的幂等哈希**（`provenance.py:440-520`），以及事件的 `event_key`。
- **K5 writer 格式、失败重试和 poison 处理、用户本人的撤回和编辑**。
- **K6 每轮注入的预算**（MEMORY 24K、EVOLUTION 8K tokens，按整条选择）。它决定每轮 prompt 的大小，直接关系性能。
- **K7 召回仍用关键词检索**。召回是检索，不是准入；SELF 里"不用向量"的定位不变。

## 4. 一次性迁移（先备份 `ingestion.db` 和受影响的主文件）

- **被改道的单元**：S7 的 agent/world 单元原本声明要写进 EVOLUTION 或 MEMORY，却被"信任改道"写进了 DDD，共约 56 条（`rerouted_from` 有记录）。按它们的原始声明移回去，走 governed edit，先给出清单。
- **积压**：61 条 `unknown_domain` 和 91 条额度推迟的单元，重新走一遍新流程。这批单元还没写进主文件，不违反 v5 原则 5。
- **标记**：按 D2 的新规则，重算 CDF 自己写入条目的 `taint:external` 标记（fixing spec C1 的迁移做法，按引用顺序做到不动点）。

**读取方先于写入方；每一步都先写会失败的测试，再实现，做 mutation check，最后提交。**

| 2 | D2 taint 拆分，加迁移脚本（先演练）；并入对方未提交的 C1 改动 | 1 | security + correctness |
| 3 | D1 删判官，加产出方的关系声明和 S7 的已有条目输入；D9、D10 | 2 | correctness + security（K3 不能被绕过） |
| 4 | D3、D4 删 S7 阈值和 S2 抽取；S7 产出事件；处理无法 resume 的会话 | 3 | correctness + operational（后台负载） |
| 5 | D5–D8、D13、D14 | 3 | correctness |
| 6 | D11 删写入额度，加 AGENT R22 文字（`backend/context/AGENT.md`） | 3 | 无（文档和配置） |

**最终不变量**（收尾时跑一次，每条都做 mutation check）：

- **I1**：S7 声明写进 EVOLUTION 的纠正，写入时不经过任何模型判定，也不被改道。
- **I2**：S1 明确的"记住"，按 agent 声明的 scope 和 type 写入，没有被判官拒收或标记 `inferred`。
- **I3**：本会话只读过工具输出时，S7 单元不带 taint，它声明的覆盖能生效。
- **I4**：引用链里有外部内容的单元带标记，并且不能覆盖已有条目；用户自己的文件仍按 K3 拒收外部来源或非用户原话的单元（现有安全测试全部通过）。
- **I5**：代码里不再有正则或关键词对单元做准入、类型或去向的判定（静态检查：`rules/ddd` 的 D4、`_volatile`、纠正正则都已删除）。
- **I6**：每个有用户消息的会话都会排上 S7；S2 不再产出认知单元。
- **I7**：聊天每轮的路径不新增任何调用；每轮注入的大小在预算之内。
- **I8**：重复纠正率只由 S7 声明的 `repeats` 计算。

**性能检查**：每一步落地后，对比 S7 复盘的耗时和后台内存推迟的次数；聊天首 token 时间不受影响，因为改动都不在聊天路径上。
