# Swarm Out E2E：七处修复

2026-11-01 按三段（派发到结果、等待和回答、验收和收尾）对照代码走了一遍。主路径都通；下面七处是"单子卡住、人没有出路"或者"丢单"。
每处写原因（读过的代码）、改法、证明它的测试。

## 1. 提交合不进去，单子永远验收不了

- **原因：** `swarm_out_settle.derive` 只在提交没封存（`unsealed`）时给"手动落地"；有 bundle 时 accept 一律是 `land`。`hive_return.land`
  遇到冲突、提交被改写、文件超出审阅范围时抛错，状态不变，下次还是 `land`。设计（run-review §1.2）写的是"合不进去时也给手动落地"。
- **改法：** 落地面板里，取回或落地报错时，错误下面给"我已手动落地"，进入现有的手动落地确认（`set_manual_landed` 本来就不看能不能合）。
  手动落地记在整单上，所以只在其它仓库都已落地（或只有这一个）时才给，免得把还没落地的仓库也算成落地。
  agent 不能替人点（手动落地只给人，已有）；skill 写明 `return-land` 被拒时让人手动落地并在单子上点它。
- **测试：** 前端：落地报错时出现按钮，点它进入手动落地确认。

## 2. 在旧面板上验收，单子被锁死

- **原因：** `set_verdict` 收任何 `ended_at`；`closed_state` 把任何 pass 判决当作已验收，不看它判的是不是现在这一次结果。
  agent 已经重跑、人在旧面板点验收：`derive` 作废这个判决、单子回到运行/待验收，但停止、重跑、丢弃全被 "this run is accepted" 拒。
- **改法：** 根上不让写：`set_verdict` 只收现在这一次最终结果的 `ended_at`（`swarm_out_results.load` 里的结果，且已是最终），否则拒
  "结果在你看过之后变了，刷新再判"。`closed_state` 同理只认判在当前结果上的 pass（读 kept 结果），已有的旧记录也不再锁。
- **测试：** 对旧 `ended_at` 的验收被拒；记录里已有一个旧判决时，`closed_state` 不是 accepted，重跑不被拒。

## 3. 派发时连接中途断开，单子丢了

- **原因：** `dispatch` 只把超时当作"可能已发出"。Hive 已经回了 200、开始流式回 SSE 之后连接被重置（`RemoteProtocolError`、`ReadError`），
  或者流结束了却没报会话，都走"没发出"：释放工作区、不记日志行、提示重发。Hive 可能已经在跑，结果再也回不来，重发还会跑重复。
- **改法：** 一条规则：**Hive 收下请求以后**（回了 200，或者请求已发出、在等回应时读超时/读断开），会话没报出来一律是"可能已发出"，
  记日志行、不释放，和超时一样。请求没发出去（连不上、Hive 拒绝）照旧是"没发出"。
- **测试：** 200 之后流断开 → `SwarmOutMaybeSent`、有日志行、没调释放；200 之后流结束没报会话 → 同上；连不上 → 照旧释放、普通错误。

## 4. Hive 拒收了回答，等待从 Needs You 消失

- **原因：** `_collect_swarm_out` 过滤掉 refused 的等待，这一单的阶段是 `needs_answer`，"待验收"那一项也不收它；Host 也不能再答一次。
- **改法：** Needs You 加一项（阻塞）："N 个 Hive 等待没用上你的回答"，说明去 Hive 自己的页面答（单子上的"打开会话"）。
- **测试：** 有 `answer_refused` 的单子时出现这一项。

## 5. Hive 中途重启，单子一直"运行中"

- **原因：** 被打断的那一轮没有结束记录，结果是 `no_record`（临时），`derive` 只要结果不是最终的就是"运行中"，不给重跑。
- **改法：** 拉结果时记下第一次看到 `no_record` 的时间（`no_record_since`，只在单子已停下时拉，见 `check_due`），按那一轮的结果
  （`no_record_of` = 结果的 `ended_at`）记，换了一轮重新计时，看到别的结果就清掉；从这里重跑时也清掉（`turn_started`）。
  更早留下、没有这个时间的记录，从它最后一次检查算。
  单子已停下、`no_record` 超过 5 分钟（排除"刚停、结束记录还没传上来"的空档）→ 阶段"已停止"，原因"中途停了，没留下结束记录"，给重跑。
- **测试：** 5 分钟内仍是运行中；超过后是已停止、动作里有重跑；拿到结束记录后清掉。

## 6. 丢弃一单时它在等 pipeline 决定：永远结不掉

- **原因：** 结单要求单子不在等待；丢弃只停聊天，Hive 上的决定还开着，所以永远不结、不释放，Needs You 里那个决定一直阻塞。
- **改法：** 已丢弃的单子结单不看"在等待"；Needs You 不再列已丢弃、已过期单子的等待。
- **测试：** 丢弃的、仍在等待的单子会结；它的等待不进 Needs You。

## 7. 落地之后又跑出新提交，没落地就被释放

- **原因：** 提交落地后 `closed_state` 不把它当已验收，结单前还能重跑；新一轮的提交仍算"已落地"，单子结掉，释放删掉工作区。
- **改法：** 落地成功、而且**每个**带提交回来的仓库都已落地或拒绝时，在结单记录里写 `code_landed_at`；`closed_state` 把它当已验收
  （和手动落地一样），之后重跑、会话写入都被拒，不会再有新提交。还有仓库没落地时不写，重跑、丢弃照常可用。
- **测试：** 落地后 `closed_state` 是 accepted、重跑被拒。

## 审查记录

correctness + state-machine 一轮：没有 HIGH。三个 MED 按原因修了：多仓库时一个仓库落地就锁住整单（改成全部落地才写）；
"手动落地"会把别的仓库也算成落地（只在最后一个仓库时给）；"没有结束记录"的时间不分轮次（按轮次记，重跑时清掉）。LOW 里修了：
旧记录没有时间（从最后一次检查算）、Needs You 按会话 id 过滤（不受 Hive 改名影响）、测试只喂参数不经过拉取（加了拉取层的测试）。

记下不修：
- 落地的那一刻如果恰好有一轮在跑（重跑在落地前一刻发出），那一轮的新提交仍会被算成已落地。落地只在"待验收"阶段提供，窗口很窄。
- 已丢弃、仍有 pipeline 决定开着的单子结掉后，Hive 的释放接口怎么处理开着的决定，没在真 Hive 上核对。

测试：`test_swarm_out_e2e_fixes.py` 和改到的套件（settle、hive_return、attention、results、swarm_out 各套件）全绿；变更点 21 个变异
（后端 18、前端 3）全部被抓到；`tsc` 通过。
