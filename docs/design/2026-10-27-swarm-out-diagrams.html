架构：东西在哪、什么跨过边界

本机 Host 负责澄清、派发和导入记录；S3 只放按 Hive 名字分开的包和记录；Hive 像一个工程师，维护自己的本地 repo，跑完按 Project Agent 定的方式交付到 repo 远端。控制只由 Host 发起；经验只在 Host 上、核对之后才进 Brain；代码不经过 Host。

一个大脑，一个写入者。 Hive 读每个 Run 的只读 DDD 快照，认知写入全部关闭，REFLECT 只导出；经验由本机判官写进 Brain。
Hive 之间互相隔离。 briefs/ 只有目标 Hive 能读，records/ 只有那台 Hive 能写、不能删、不能覆盖；参考实例读不到任何包和记录。
交付方式由 Project Agent 定。 landing: {via, approval}：直接 push、开 PR、发 CR，或等你批准再 push。只有 Hive daemon 能交付；远端在这期间前进了，就在同一个 Run 里 rebase、重测再交付。

流程：一个 Run 从说需求到交付

从左到右是五个参与方，从上到下是时间。灰底横条是阶段；琥珀色箭头是 XG 自己的动作，只出现在说需求、点派出去和回答问题（含批准 push）三处；黑色粗箭头是交付到 repo 远端。
