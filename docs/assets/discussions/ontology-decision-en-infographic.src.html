THE TWO LAYERS OF ONTOLOGY

Ontology isn't a knowledge graph — it's a decision layer

One word, two camps using it — an order of magnitude apart in meaning
🏷️ THE NOUN CAMP
Classification + Relations
Tag each thing (contacts: family / colleague)
Link things together (Zhang —is boss of→ Li)
Knowledge graphs live here
→ lets you «find it»
can look up, but can't act
⚡ THE VERB CAMP
What you can DO + who owns the outcome
Action: what you can do to the world (order / configure / kill)
Function: decision rules, constraints, tradeoffs
Proposal: AI proposes → human approves → system executes → fully audited
→ lets you «make the call»
with tradeoffs, ownership, traceability
The noun camp lets you see the world; the verb camp lets you change it. A pure knowledge graph stops at the noun layer.
ONE 4-RUNG RULER · EACH SUBSYSTEM IS A RUNG

From prediction, all the way to decision

Most "data capabilities" stop at prediction. SwarmAI walks the whole chain.

ONE IDEA · TWO ENGINES

Why knowledge and code don't share one engine

Same "classification + relations" — but opposite lifecycle needs

💛 Knowledge side

Cares about: should this be forgotten?
Objects: memory + 9 project knowledge bases
Engine: ddd_entry_lifecycle.py (shared)
Lifecycle: Darwinian fade → forget
Use it or lose it: referenced → +1 stronger; idle → dormant → archived

💚 Code side

Cares about: who's connected to whom right now?
Objects: a call graph of 18,034 functions
Engine: code_intel/graph_store.py (separate)
Lifecycle: on any code change, invalidate → rebuild, no fade
Changing a function? One graph query lists every caller — you know the blast radius before you touch it
They share the idea of Ontology (nodes + edges + classification), but opposite lifecycles → two separate engines
