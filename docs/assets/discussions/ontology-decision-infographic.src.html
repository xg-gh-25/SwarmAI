ONTOLOGY 的两层

Ontology 不是知识图谱,是决策层

同一个词,两拨人在用,含义差着一个数量级
🏷️ 名词派
分类 + 关系
每个东西归一类(通讯录:家人/同事)
东西之间连线(张三 —是老板→ 李四)
知识图谱活在这层
→ 让你「查得到」
能查,但不能动
⚡ 动词派
能做什么 + 谁担后果
Action:能对世界做什么(下单/改配置/杀进程)
Function:决策规则、约束、权衡
Proposal:AI 提议→人审→执行→全程审计
→ 让你「拍得了板」
带取舍、担后果、可追溯
名词派让你看清世界,动词派让你改变世界。 纯知识图谱停在名词层。

为什么知识和代码不共用一个引擎

同样是「分类 + 关系」,但生命周期需求正相反

💛 知识侧

关心:这条该不该被遗忘?
对象:记忆 + 9 个项目知识库
引擎:ddd_entry_lifecycle.py(共享)
生命周期:达尔文式 淡出 → 遗忘
用进废退:被引用 +1 变强,长期没用 → 休眠 → 归档

💚 代码侧

关心:现在谁跟谁连着?
对象:18,034 函数的调用图
引擎:code_intel/graph_store.py(独立)
生命周期:代码一改 失效 → 重建,不淡出
改一个函数?一次图查询列全 caller,动手前就知道波及面
共享 Ontology 的思想(节点+边+分类),但生命周期正相反 → 拆成两套
